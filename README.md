# warehouse-sim

브라우저에서 도는 3D 물류 창고 시뮬레이터입니다. 로봇이 선반에서 상자를 꺼내 작업대로 가져오고, 물건은 컨베이어를 타고 포장을 거쳐 트럭에 실립니다. 손잡이를 돌리면 흐름이 어디서 막히는지가 화면과 숫자로 보입니다.

- `sim.js`: 창고 로직. 화면 없이 혼자 돕니다.
- `index.html`: three.js 화면. 로직 상태를 읽어서 그리기만 합니다.

## 실행

`index.html` 을 브라우저로 열거나, 폴더에서 정적 서버를 띄웁니다.

```
python -m http.server 8728 -b 127.0.0.1
```

로직 검사는 Node 로 돌립니다. 조건별로 2만 틱씩 돌리며 로봇 겹침, 주문 누락, 교착, 역주행, 재고 음수를 확인합니다.

```
node sim.js
```

## 상태

### 어디까지 됐나

| 작업 단위 | 상태 |
| --- | --- |
| `sim.js` 로직: 통로 5개·3단 선반·배정 2규칙·작업대 4곳→컨베이어→포장→출고 적치→트럭·상자 반납·일방통행·재고, 입고(발주→입고 트럭 `inboundEvery` 240틱·24상자→하역장→지게차 `forklifts` 1대가 선반 보충) | `node sim.js` → `ok` (6조건 × 2만 틱, 겹침·주문 누락·역주행·재고·교착·입고 대기 짝 검사). 트럭 없음/있음 포장 수 동일 643 |
| `index.html` 화면 (three.js 0.160.0 CDN) | 지게차가 하역장↔선반을 다님, 패널에 "하역장 N" 숫자. 입고 트럭·하역장 더미 그림과 지게차 대수 손잡이는 없음. 지게차가 통로 안을 다니는 것은 사용자가 로컬에서 확인(11-22). GitHub Pages(https://ellencia.github.io/warehouse-sim/)는 첫 판만 사용자가 확인(11-22). 미확인: 푸시 뒤 Pages 에 지게차가 보이는지 |
| `measure.js` 일방통행 손익 측정 | 커밋 `decee8a` |

- 일방통행 손익 (`node measure.js 20 120`, 입고 흐름 넣은 뒤, 2만 틱·씨앗 5개 평균 포장 수, 양방향 → 일방통행): 분당 120 에서 7대 2449 → 2384 (0/5 승), 8대 2615 → 2698 (5/5 승), 12대 3045 → 3843. 갈리는 지점 7–8대 사이. 분당 20 은 4대 1661 → 1401 로 손해, 5대 1679 → 1666, 6대부터 차이 ±4 이내
- 지게차 대수 (로봇 12·분당 120·일방통행, 씨앗 5개, 저장소에 스크립트 없어 기록가가 재현): 포장 수 1대 3843 → 2대 3818 로 처리량 차이 없음, 하역장 대기(매 틱 평균) 11.2 → 1.4상자

### 다음

- 입고 쪽 남은 것: 지게차 대수 손잡이, 입고 트럭·하역장 그림, 품절 주문 대기 시간 계측
- 재고 색 표시(파랑 농담이 잘 안 읽힘)·일방통행 화살표가 선반에 가림, 뒷벽 랙·관제 화면·포장 작업자는 아직 장식

### 하면 안 되는 것

- 입고는 임시(`sim.js` `inbound()` 의 ponytail 주석): 트럭 하역 시간 없음, 지게차는 로봇 `occ` 격자에 안 올라가 통로를 막지 않음. 지게차가 막는 효과를 보려면 격자에 올리고 교착 검사를 같이 볼 것
- 출고 적치에 한도를 넣지 말 것: 로봇 단계와 트럭 단계를 따로 보려고 일부러 끊어 둔 것이고, 넣으면 "트럭이 로봇 단계에 영향을 줬다" 검사가 깨짐
- 교착 풀기는 임시(길이 없으면 6틱 뒤 빈 옆 칸으로 무작위로 비킴). 교통 규칙을 바꿀 땐 이 자리와 "마지막 2000틱 완료 0건" 교착 검사를 같이 볼 것
- 재고 배열은 Uint8 이라 음수가 255로 보임. 재고 검사는 `<= STOCK_CAP` 로 이걸 잡으니 타입을 바꾸면 검사도 같이 바꿀 것
- 주문→트럭을 한 숫자로 합쳐 보여 주지 말 것: 트럭 대기가 평균을 지배해 로봇 쪽 변화가 안 읽힘
