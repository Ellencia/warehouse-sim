# warehouse-sim

브라우저에서 도는 3D 물류 창고 시뮬레이터입니다. 로봇이 선반에서 상자를 꺼내 작업대로 가져오고, 물건은 컨베이어를 타고 포장을 거쳐 트럭에 실립니다. 손잡이를 돌리면 흐름이 어디서 막히는지가 화면과 숫자로 보입니다.

- `sim.js`: 창고 로직. 화면 없이 혼자 돕니다.
- `index.html`: three.js 화면. 로직 상태를 읽어서 그리기만 합니다.

## 실행

`index.html` 을 브라우저로 열거나, 폴더에서 정적 서버를 띄웁니다.

```
python -m http.server 8728 -b 127.0.0.1
```

로직 검사는 Node 로 돌립니다. 조건별로 2만 틱씩 돌리며 로봇 겹침, 주문 누락, 교착, 역주행, 재고 음수를 확인합니다.

```
node sim.js
```

## 상태

### 어디까지 됐나

| 작업 단위 | 상태 |
| --- | --- |
| `sim.js` 로직: 통로 5개·3단 선반·배정 규칙 2가지(nearest, longestIdle)·작업대 4곳→컨베이어→포장→출고 적치→트럭·상자 반납·일방통행·재고 | `node sim.js` → `ok`. 6조건 × 2만 틱에서 겹침·주문 누락·역주행·재고·교착 검사 통과 |
| `index.html` 화면 (three.js 0.160.0 CDN) | 로직과 같은 첫 커밋 `cb69f6d`, origin/main 과 같음. GitHub Pages(https://ellencia.github.io/warehouse-sim/)에서 사용자가 확인(11-22) |

- 일방통행 손익 (`node measure.js`, 11-22, 2만 틱·씨앗 5개 평균 포장 수, 양방향 → 일방통행): 주문이 넘치는 분당 120 에서 7대 2444 → 2389 (씨앗 0/5 승), 8대 2610 → 2701 (5/5 승), 12대 3037 → 3814. 갈리는 지점은 7대와 8대 사이. 분당 20 에서는 4대까지 손해(1660 → 1403), 5대부터는 둘 다 주문을 다 처리해 차이 없음. 이 숫자는 임시 재입고(240틱) 기준
- 트럭 없음/있음 포장 수 동일 660: 트럭이 로봇 단계에 영향을 주지 않음

### 다음

- 임시 재입고(바닥나고 240틱 뒤 저절로 가득)를 진짜 입고 흐름(트럭 → 지게차 → 선반 보충)으로 교체
- 입고 흐름을 바꾼 뒤 `node measure.js` 다시 돌려 위 숫자와 비교
- 재고 색 표시(파랑 농담이 잘 안 읽힘), 일방통행 화살표가 선반에 가리는 문제
- 뒷벽 랙·지게차·관제 화면·포장 작업자는 아직 장식

### 하면 안 되는 것

- 출고 적치에 한도를 넣지 말 것: 로봇 단계와 트럭 단계를 따로 보려고 일부러 끊어 둔 것이고, 넣으면 "트럭이 로봇 단계에 영향을 줬다" 검사가 깨짐
- 교착 풀기는 임시(길이 없으면 6틱 뒤 빈 옆 칸으로 무작위로 비킴). 교통 규칙을 바꿀 땐 이 자리와 "마지막 2000틱 완료 0건" 교착 검사를 같이 볼 것
- 재고 배열은 Uint8 이라 음수가 255로 보임. 재고 검사는 `<= STOCK_CAP` 로 이걸 잡으니 타입을 바꾸면 검사도 같이 바꿀 것
- 주문→트럭을 한 숫자로 합쳐 보여 주지 말 것: 트럭 대기가 평균을 지배해 로봇 쪽 변화가 안 읽힘
